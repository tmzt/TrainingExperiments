# Genius training corpus (cleaned)

Generated by `scripts/clean_genius_corpus.py` in the Highbay repo from
`data/genius/mobile_data_prompts.jsonl` (92) and `data/genius/prompts.jsonl`
(50). **Do not hand-edit** - fix the source or the script and regenerate.

| file | contents |
|---|---|
| `genius_corpus_clean.jsonl` | 142 records, `{user_input, output_ast}`, true JSONL, UTF-8 without BOM |
| `genius_chatml.jsonl` | the same 142 as ChatML `{messages: [system, user, assistant]}`, AST as canonical JSON in the assistant turn |

142 records, 71 `SCHEMA_SUGGESTION` / 71 `PIPELINE`, 142/142 well-formed
against the validator in the script. No duplicate `user_input`s across the two
sources.

## What was cleaned, and why

The sources are Gemini-generated training data, so they carry generation
artifacts a hand-authored schema would not. Each of these was measured, and
each fails **silently** if left in.

**Two on-disk formats.** `mobile_data_prompts.jsonl` is real JSONL carrying a
UTF-8 BOM - with plain `utf-8`, the *first* record and only the first fails to
parse, which reads like one stray malformed line rather than an encoding
problem. `prompts.jsonl` is a pretty-printed JSON **array** despite the
`.jsonl` name, and reading it line-by-line does not error: it yields
`schema_mutations` fragments that look like records. Output here is true JSONL,
UTF-8, no BOM.

**`UPDATE_RECORD.payload` was spelled two ways.** `payload` is not a `str|dict`
union - it is determined by the action:

| action | payload | n |
|---|---|---|
| `SEND_NOTIFICATION` | message string | 28/28 |
| `CALCULATE` | description string | 20/20 |
| `UPDATE_RECORD` | field -> value **map** | 23/23 |

...but the generator wrote that map as an object 8 times and as a *stringified*
object 15 times - `{"status": "Warm"}` beside `"{\"status\": \"Archived\"}"`.
Identical meaning, two spellings, no rule available to learn, so at ~114
training records the corpus was teaching a coin flip. The maps win here; the
strings are parsed back. **Direction matters**: normalizing the other way
promotes the artifact to ground truth.

## What was deliberately left alone

* `conditions[].value` is `str` x44 / `int` x4 and that union is **real** -
  `total_amount > 500` and `age_days > 30` sit beside string comparisons.
* Table names, column names, `ui_prompt` wording, and which columns a
  suggestion proposes. Those are the content; only spelling was touched.

## Notes for anyone consuming this

* **`schema_mutations` has two shapes.** `CREATE_TABLE` carries
  `{action, name}`; `ADD_COLUMN` carries `{action, table, column_name, type}`.
  Reading `m["table"]` undercounts tables and silently skips every table
  creation.
* **Do not infer a column type per AST field.** `pandas`/Arrow
  (`load_dataset("json", ...)`) will either refuse - `cannot mix struct and
  non-struct, non-null values` - or, on one file alone, silently unify the two
  mutation shapes into one 5-field struct and backfill nulls, at which point
  only 46/92 ASTs survive the round trip. Treat the output side as opaque text;
  `genius_chatml.jsonl` already is.
* **Vocabularies**, should you want closed enums: intent `PIPELINE |
  SCHEMA_SUGGESTION`; trigger `ON_CREATE | ON_UPDATE | ON_DELETE | SCHEDULED`;
  action `SEND_NOTIFICATION | UPDATE_RECORD | CALCULATE`; column `NUMBER | DATE
  | STRING | BOOLEAN | RELATION`.
* **Scope.** 100+ distinct tables, including `Projects` and `Expenses`. There
  is **no `Budget` table**, which matters if the target vocabulary is
  Project/Expense/Budget.
* **Size.** 142 records is ~114 after a held-out split. Small for teaching a
  JSON schema from scratch; expect memorization and read a large train/eval gap
  as a corpus problem rather than a hyperparameter one.
